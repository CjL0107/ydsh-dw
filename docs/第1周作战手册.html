子任务 2

开发环境搭建：Docker + Hive + MySQL

三个容器一键起，这是本周最容易卡住的一步

2 课时

启动

cd "C:\Users\Lenovo\Desktop\ydsh-dw"

# 首次必须带 --build：要先把 MySQL 驱动打进 Hive 镜像
docker compose up -d --build

# 等 60~90 秒，确认三个容器都是 Up（不是 Restarting / Exited）
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

验证

# 1) 元数据库正常
docker exec -it mysql mysql -uroot -proot -e "use metastore; show tables;"

# 2) Hive 可连接
docker exec -it hive-server beeline -u "jdbc:hive2://localhost:10000/"
# 进入后执行：show databases;  然后 exit;
必踩的坑：Metastore 反复重启

官方 apache/hive 镜像不自带任何数据库驱动。如果你照网上教程直接 docker run 配 DB_DRIVER=mysql，一定报 No suitable driver found。

本项目的 Dockerfile.hive 已经用多阶段构建把 mysql-connector-j 打进去了，所以只要带 --build 就不会踩这个坑。看日志确认：docker logs hive-metastore

坑 2：容器 Up 但 beeline 连不上

HiveServer2 冷启动要 40～90 秒，Up 只代表进程活着不等于 10000 端口在听。等一会儿再连，或 docker logs -f hive-server 看到 Service listening on port 10000 再试。

验收

三个容器均 Up；beeline 能进交互界面，show databases; 返回 default。这一步过了，本周最难的部分就过去了。

子任务 6

清洗（一）：缺失值诊断与处理

年龄均值填充、邮箱留空打标、上架日期按品类回填

1 课时

docker exec -i hive-server beeline -u "jdbc:hive2://localhost:10000/default" -f /sql/clean/clean_product.sql

清洗策略与业务理由（答辩必问）

字段策略为什么这么做
age[1,120] 之外视为脏值，与空值一起用全体有效均值 41 填充；加 age_is_filled 标记用户维度删行会连带删掉该用户订单关联，代价太大
email保留 NULL + email_is_missing 标记缺失 19.3% 无法推断，编造假邮箱比留空更危险
gender / member_level空值填 未知同义归并（男/M/male）属第 2 周任务，本周只补缺失
launch_date用同品类最早日期回填 + 标记位用"当前日期"回填会把老商品误判成新品，方向反了
验收

dwd_user：1000 行，年龄空值 0、异常 0，sum(age_is_filled)=78；dwd_product：上架日期空值 0、填充 11 条。

子任务 7

清洗（一）：重复值检测与去重

ROW_NUMBER + 业务排序规则，15600 → 15000

1 课时 
docker exec -i hive-server beeline -u "jdbc:hive2://localhost:10000/default" -f /sql/clean/clean_order.sql

# 单独核对
docker exec -i hive-server beeline -u "jdbc:hive2://localhost:10000/default" -e "
SELECT COUNT(*) AS rows_after,
       COUNT(*) - COUNT(DISTINCT order_id) AS still_dup
FROM ydsh_dwd.dwd_order;"

去重逻辑（评分核心）

ROW_NUMBER() OVER (
  PARTITION BY order_id
  ORDER BY order_time  DESC,   -- 1. 保留最后一次写入
           pay_amount DESC,   -- 2. 时间相同取成交额大的
           order_date DESC,   -- 3. 再按下单日期
           rn_key      DESC   -- 4. 整行指纹兜底，保证可复现
) = 1
为什么必须写全排序

只写 PARTITION BY order_id 不指定 ORDER BY，Hive 无序，每次跑结果可能不同——不可复现是硬伤，老师一问就露。第 4 个 rn_key 是整行内容指纹，用来消除所有并列情况。

验收

dwd_order = 15000 行，still_dup = 0，删除 600 行与预评估发现的数量完全吻合。
