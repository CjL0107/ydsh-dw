## 一、完整性（Completeness）—— 字段空值率

| 表.字段 | 总行数 | 空值数 | 空值率 | 判定 |
|---|---:|---:|---:|---|
| ods_user.age | 1,000 | 51 | 5.10% | ⚠️ 需处理 |
| ods_user.gender | 1,000 | 84 | 8.40% | ⚠️ 需处理 |

> **口径说明**：Hive 从 TEXTFILE 读入时，空字段在 `STRING` 列保留为 `''`，在 `INT/DECIMAL` 列转为 `NULL`。
> 因此判定语句必须写成 `nvl(trim(col),'') = ''`，只写 `IS NULL` 会漏掉 353 条记录中的绝大部分。

## 二、唯一性（Uniqueness）—— 主键重复

| 表 | 主键 | 重复组数 | 涉及行数 | 需删除行数 |
|---|---|---:|---:|---:|
| **ods_order** | order_id | **586** | **1,186** | **600** |
| ods_user | user_id | 0 | 0 | 0 |
| ods_product | product_id | 0 | 0 | 0 |
| ods_store | store_id | 0 | 0 | 0 |
| ods_order_item | item_id | 0 | 0 | 0 |
| ods_user_behavior | behavior_id | 0 | 0 | 0 |

### 重复订单的两类形态（去重策略必须分开）

| 类型 | 组数 | 成因 | 处理方式 |
|---|---:|---|---|
| A｜整行完全重复 | **388** | 调度重跑 / 重复导入，10 个字段逐字节相同 | 保留任意 1 条即可，无信息损失 |
| B｜主键重复但内容不同 | **198** | 业务侧重复提交，或状态未回写（同一 order_id 金额不同） | 不能随便删，须按业务规则选"最可信"的一条 |

> **判据**：按 order_id 分组后，若组内 `COUNT(DISTINCT 全字段指纹) = 1` 则为 A 类，`> 1` 则为 B 类。
> 注意不能用 `COUNT(*) = COUNT(DISTINCT 指纹)` 判断——那样会把 3 条完全相同的记录误判为"内容不同"。

### 4.2 维度口径一致性

| 检查项 | 结果 | 说明 |
|---|---:|---|
| 同一城市归属不同省份的冲突数 | 0 | ✅ 用户表与门店表省市口径一致 |
| 用户城市未被门店覆盖的组合数 | 27 / 63 | 正常现象：用户分布广于门店覆盖，不属脏数据 |

> **这条很重要**：很多人做"用户所在城市门店销售额"分析时会发现对不上，误以为是脏数据。实际是**用户城市 ≠ 下单门店城市**——订单表里的 `store_id` 才是成交门店，用用户城市去关联门店是逻辑错误，不是数据问题。
